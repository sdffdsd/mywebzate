# 技术路线：不备案前提下的「国内尽量可达」个人站

> 适用前提：**不做 ICP 备案**（你已确认）。站点内容为个人图文 + 动效 + 音频，日访客个位数。
> 结论先说：**不备案就无法使用境内 CDN 节点，因此"国内 IP 均可直接访问"无法作为承诺**。
> 本方案的目标是把它变成一件**概率足够高、可测量、可切换**的事。

---

## 1. 为什么 Cloudflare 免费版达不到「国内均可直接访问」

| 事实 | 影响 | 依据 |
| --- | --- | --- |
| Cloudflare 中国网络（境内节点）要求 **Enterprise 套餐 + 中国网络订阅 + 域名 ICP 备案 + 京东云内容审核** | 个人站直接用不了境内节点 | [Cloudflare China Network 文档](https://developers.cloudflare.com/china-network/get-started/) |
| `*.pages.dev` / `*.workers.dev` 在国内长期被 DNS 污染/阻断 | **绝不能拿平台默认域名当正式入口** | 多篇实测（[示例](https://www.hexvork.com/posts/cfpages-cn-access)） |
| 免费版 + 自定义域名，流量仍落在境外 PoP（香港/新加坡/日本/美西） | 延迟 150–350ms，晚高峰丢包明显；偶发 SNI 阻断 | Cloudflare 免费版不接入境内节点 |
| 「优选 IP / CNAME 反代」只能缓解 | 随时可能失效，且属灰色手段 | [FaaS-in-China 项目](https://github.com/jemerci/pages_speedup-FaaS-in-China) |

**所以第一个动作是**：注册自己的域名，用自定义域名提供服务（这一步能把"完全打不开"降级为"有时慢"）。

## 2. 目标架构：双出口 + 分线路解析

```text
                    ┌──────────────────────────────┐
   国内访客 ────────▶│  香港/新加坡 VPS（备用出口）   │  Node 静态服务 + /api/visit
                    │  server/index.mjs            │  延迟 30–80ms，无需备案
                    └──────────────────────────────┘
                                  ▲
        DNSPod 分线路解析           │ 国内线路 → A 记录（VPS IP）
        www.example.com ──────────┤
                                  │ 海外线路 → CNAME
                                  ▼
                    ┌──────────────────────────────┐
   海外访客 ────────▶│  Cloudflare Pages + Workers   │  免费，全球 Anycast
                    │  dist/ + functions/api/visit  │
                    └──────────────────────────────┘
```

同一份 `dist/` 产物、同一份 `src/lib/visit-core.ts` 逻辑，分别放飞两个出口。
单点故障时改一条 DNS 记录即可切换 —— 这是不备案方案里性价比最高的一层保险。

> **当前状态：只启用路线 A（Cloudflare 单出口 + 灾备子域）。**
> 上图里的香港出口是预留的升级路径，尚未部署；`server/index.mjs` 与 CI 里的 `deploy-vps` 作业都已就绪，
> 等你用第 6 节的拨测数据判断"是否需要"之后再启用。

## 3. 两条落地路线

| | 路线 A：只用 Cloudflare ✅ **已采用** | 路线 B：Cloudflare + 香港 VPS（备选） |
| --- | --- | --- |
| 月成本 | ¥0 | ¥25–40（轻量服务器） |
| 国内可达性 | 中等：多数时候能开，晚高峰慢/偶发失败 | 较高：直连 + 延迟低，明显更稳 |
| 微信内打开 | 风险较高（未备案域名常被拦） | 同样有风险，域名未备案是主因 |
| 运维量 | 几乎为零 | 每台机器要打补丁、看进程、续证书 |
| 域名形态 | apex 与 `www` 都可用，NS 托管 Cloudflare | 主入口只能用 `www`，apex 需自建 301 |

**执行顺序**：按路线 A 上线 → 第 6 节拨测拿基线 → 若国内成功率/速度不可接受，再按第 4.2 与第 5 节升级到路线 B。
两者互不阻塞，代码同时支持。

> 关于 EdgeOne Pages：它的免费版很香，但**境内加速区域要求备案**；不备案只能选「全球可用区（不含中国大陆）」，
> 那条线路没有境内节点，国内可达性不会优于 Cloudflare（[域名管理文档](https://edgeone.cloud.tencent.com/pages/document/175191784523485184)）。
> 所以它在本方案里只是**第三条独立出口**，不是解药。`edgeone.json.example` 已留好位置。

## 4. DNS 配置模板

### 4.1 路线 A：NS 全托管 Cloudflare（**当前采用**）

域名接入 Cloudflare 成为 zone，DNS 记录由 Cloudflare 管理。逐步操作见
[`上线手册-路线A.md`](上线手册-路线A.md)，最终记录形态如下：

| 类型 | 名称 | 内容 | 代理状态 | 说明 |
| --- | --- | --- | --- | --- |
| CNAME | `example.com`（apex） | `<project>.pages.dev` | 橙云 | 绑 apex 自定义域名时 Cloudflare 自动创建，别手改 |
| A | `www` | `192.0.2.1` | 橙云 | 只为让 Bulk Redirect 能接管 `www` 请求（[官方做法](https://developers.cloudflare.com/pages/how-to/www-redirect/)） |
| CNAME | `cf` | `<project>.pages.dev` | 橙云 | 备用入口，主线异常时可临时引导（可选） |
| TXT | `_acme-challenge` | Cloudflare 自动写入 | — | 证书验证用，**不要删** |

配套整站跳转：`www` → `https://example.com` 301（Bulk Redirects）。

### 4.2 路线 B：NS 放 DNSPod + 香港出口（备选，未来升级用）

如果要加一台香港机器做国内直连，必须把 NS 换成 DNSPod 才能分线路解析：

| 主机记录 | 线路 | 记录类型 | 值 | 说明 |
| --- | --- | --- | --- | --- |
| `www` | 默认 | CNAME | `<project>.pages.dev` | 海外主线（Cloudflare Pages） |
| `www` | 境内 | A | `<香港 VPS IP>` | 国内直连 |
| `@` | 默认 | A | `<香港 VPS IP>` | 由香港机器对 apex 做 301 跳到 `www`（见第 5 节 Caddy 配置） |
| `cf` | 默认 | CNAME | `<project>.pages.dev` | 备用入口 |

切换到路线 B 前必须知道的四件事：

1. **Cloudflare Pages 的 apex 与子域名规则不同**：`www`、`cf` 这类**子域名**可以用外部 DNS 的 CNAME 接入
   （域名不必是 Cloudflare zone）；但 **apex（`example.com`）必须把域名作为 Cloudflare zone 并将 NS 指向 Cloudflare**
   （[官方文档](https://developers.cloudflare.com/pages/configuration/custom-domains/)）。
   → 保留 DNSPod 分线路就意味着**主入口只能用 `www`**，apex 交给香港机器跳转。
2. **DNSPod 的 URL 转发（显性/隐性）要求转发前后域名都已完成工信部备案**，未备案域名无法添加
   （[DNSPod 文档](https://support.dnspod.cn/dns/help-redirect-url/)）。
   → 不备案时 apex 的跳转只能自己实现：让 apex 解析到香港机器，由 Caddy 做 301（第 5 节已给出配置）。
3. **不要**把未备案域名解析到**境内** IP —— 那是明确违规，会被拦截。解析到香港/境外 IP 不需要备案。
   同理，别把未备案域名绑到阿里云 OSS / 腾讯云 COS 的**境内**节点或境内 CDN。
4. DNSPod **免费版**就含 `默认 / 电信 / 联通 / 移动 / 教育网 / 广电 / 铁通 / 境内 / 境外` 线路，
   做「境内走香港、境外走 Cloudflare」够用了，不需要买套餐（[线路说明](https://docs.dnspod.cn/dns/dns-record-line/)）。

## 5. 香港出口部署（路线 B，备选，当前未启用）

```bash
# 机器上准备（Debian/Ubuntu，Node ≥ 22.12）
apt update && apt install -y nodejs npm rsync caddy

# 首次部署
mkdir -p /var/www/personal-site
# 本地执行（或在 GitHub Actions 里执行，secrets 已留好）
# 下面两行的 主机IP 要换成真实值 —— 不要写成 <主机IP>，尖括号会被 shell 当重定向
rsync -avz --delete ./dist/ root@主机IP:/var/www/personal-site/
rsync -avz server/ src/lib/ package.json root@主机IP:/opt/personal-site/
```

`/etc/systemd/system/personal-site.service`：

```ini
[Unit]
Description=personal-site static server
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/personal-site
Environment=PORT=8080
Environment=HOST=127.0.0.1
Environment=VISIT_DATA_FILE=/var/lib/personal-site/visits.json
ExecStart=/usr/bin/node server/index.mjs --root /var/www/personal-site
Restart=always
RestartSec=3

[Service]
# 顺手加固：只读文件系统，除数据目录外不可写
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

`/etc/caddy/Caddyfile`（自动申请并续期 Let's Encrypt 证书）：

```caddyfile
www.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}

# apex 301 到 www：未备案时不能用 DNSPod 的 URL 转发，只能在机器上自己跳
example.com {
    redir https://www.example.com{uri} permanent
}
```

```bash
systemctl daemon-reload
systemctl enable --now personal-site
systemctl reload caddy
```

> 注意：**别在香港机器前面再套 Cloudflare 代理**（小黄云）。那等于把流量又绕回境外 PoP，
> 白花了这台机器的钱。要让国内用户直连，就用 DNS 直连 A 记录。

## 6. 上线验收：必须真的拨测

不测就等于没做。工具与判据：

- **多线路拨测**：[itdog.cn](https://www.itdog.cn/) 的全国 Ping / HTTP 测速，或 boce.com、站长工具。
- **测点覆盖**：移动 / 联通 / 电信 × 华东 / 华南 / 华北 / 西南 ≥ 12 个点。
- **验收基线**：

| 指标 | 路线 A（CF） | 路线 B（香港直连） |
| --- | --- | --- |
| 成功率 | ≥ 90% | ≥ 98% |
| 首字节 TTFB | < 1.5s | < 300ms |
| 首屏完全加载 | < 5s | < 2.5s |

- **节奏**：上线当天测一次存基线；之后每周固定时间测一次，观察晚高峰（20:00–23:00）表现。
- **记录**：把每次结果（时间、成功率、异常省份）记在仓库 `docs/拨测记录.md`，出现劣化时才知道是运营商问题还是自己改坏了。

## 8. 风险与红线

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **版权** | 音频/图片是个人站最容易被投诉下架的点 | 只用原创 / CC0 / 已授权素材；示例音频是脚本合成的 |
| 内容合规 | 个人非经营性站点，不得涉新闻、视听节目、经营性服务 | 保持纯个人分享；别放广告联盟、付费入口 |
| 境内节点误用 | 未备案域名绑境内 CDN/OSS 会被拦截 | 只用境外节点；CDN 用 Cloudflare |
| 优选 IP 灰区 | 随时失效，且非官方支持路径 | 只当临时缓解，不做唯一入口 |
| 单厂商故障 | CF 故障或被针对性阻断时整站失联 | 保留香港出口 + `cf` 备用子域名 |
| 数据丢失 | KV / JSON 计数没有备份 | 每周导出一次；计数丢了不影响内容 |
| 微信内打开 | 未备案域名在微信里可能被拦截或提示 | 提前在微信内实测；重要分享场景要接受这个风险 |

## 9. 什么时候应该回头备案

出现下面任一条，备案就不是"可选优化"而是必须：

- 要求国内**接近 100%** 可达，或明确不能接受晚高峰变慢；
- 主要传播渠道是**微信**（未备案域名被拦的概率显著更高）；
- 需要国内的低延迟稳定体验（境内节点 RTT < 50ms）；
- 以后要做登录、支付、评论等经营性功能。

备案后的迁移路径（本仓库已为此设计）：

1. 域名完成 ICP 备案（个人非经营性免费，周期约 1–3 周，需国内云资源作为接入）；
2. 静态产物原样上传到 **腾讯云 EdgeOne Pages「全球可用区（含中国大陆）」** 或阿里云 OSS + CDN；
3. 在页脚展示备案号（`src/components/SiteFooter.astro` 里已留好 `icp` 变量）；
4. `src/lib/visit-core.ts` 与 `functions/api/visit.ts` 逻辑不变，换数据存储绑定即可。

**代码零改动**是这套架构最主要的价值：不备案和备案只差一次 DNS 切换。
